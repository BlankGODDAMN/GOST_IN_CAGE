# Стенд: оракул ГОСТ в Docker + атака LadderLeak на хосте

Полная симуляция атаки по частичной утечке нонса (Hidden Number Problem):

- **Оракул** (`oracle_server.py`, в Docker) — «жертва». Держит секрет `x` только
  в памяти, наружу отдаёт **только** открытый ключ и подписи. В трейсе SIGN
  маскирует тайминг уязвимой лестницы под две метки времени.
- **Атака** (`attack_client.py`, на хосте) — сама вычисляет `t` из меток времени,
  сама решает, у каких подписей старшие биты нонса нулевые, и решёткой (CVP)
  восстанавливает `x`. Проверка успеха — только по `d·G == Y`.

Оракул **никогда** не отдаёт `t`, нонс `k` или секрет `x`. Биты вычисляет атака.

## Побочный канал (что именно «утекает»)

Из `(r, s, e)` старший бит нонса вычислить нельзя — нужен физический канал.
Здесь это **реальное время работы лестницы**: у не-constant-time умножителя
`[k]G` число шагов = `bit_length(k)`, поэтому оракул реально тратит
`bit_length(k)·STEP_MS` мс (busy-wait) и печатает две **измеренные** метки:

```
[12:30:22.014321] начинаю подписывать
· этап 1/3
· этап 2/3
· этап 3/3
[12:30:22.116493] подпись готова        <- разница ≈ bit_length(k)·квант
r=...
s=...
e=...
```

Атака **сама мерит** задержку из двух меток, **сама калибрует квант** по
известному `w` (оракул его не сообщает), оценивает `t̂ = round(задержка/квант)`,
затем `lz = w - t̂`. Если `lz >= L` — старшие `L` бит нонса нулевые → годный
HNP-образец. Это методология LadderLeak: **фильтровать подписи с ведущими
нулями нонса** (цена — ~`2^L` запросов на один годный образец; на 512-бит дорого).
Редкая ошибка замера не опасна: неверный ключ не пройдёт проверку `d·G == Y`.

## Запуск

### 1. Поднять оракул (Docker)

Из папки `docker_hnp/`:

```bash
docker compose up --build
```

или вручную из **корня проекта**:

```bash
docker build -f docker_hnp/Dockerfile -t gost-oracle .
docker run --rm -p 31337:31337 -e GOST_CURVE=A gost-oracle
```

В логах контейнера напечатается секрет `x` — это **ground truth для оператора**
(сверить с восстановленным ключом), по сети он не уходит.

Кривая: `GOST_CURVE=A` — 512-бит (по умолчанию), `B` — короткая тестовая (быстро).
Квант времени `ORACLE_STEP_MS` (умолчание 0.2 для A, 5 для B; поставь `1000` —
метки станут «целыми секундами» для наглядного ручного демо).

⚠️ На 512-бит сбор дорог: годный образец бывает ~раз в `2^L` подписей. Начинай
с умеренного `L` (напр. `python attack_client.py 6`) и запасись временем.

### 2. Пощупать вручную (как настоящий nc-чат)

```bash
nc 127.0.0.1 31337
PUBKEY
SIGN привет
QUIT
```

### 3. Запустить атаку (на хосте, где стоят fpylll + gostcrypto)

```bash
python attack_client.py            # L=3 по умолчанию, без BKZ
python attack_client.py 4          # L=4
python attack_client.py 4 20       # L=4, BKZ-20 (для трудных случаев)
```

Другой адрес оракула:

```bash
ORACLE_HOST=127.0.0.1 ORACLE_PORT=31337 python attack_client.py 3
```

## Файлы

| Файл | Где работает | Роль |
|---|---|---|
| `oracle_server.py` | Docker | подписывающий оракул (жертва) |
| `attack_client.py` | хост | автоматическая атака (решётка) |
| `Dockerfile` | — | образ оракула (context = корень проекта) |
| `docker-compose.yml` | — | запуск оракула одной командой |

`gost.py` и `lattice_attack.py` берутся из корня проекта (единый источник).
